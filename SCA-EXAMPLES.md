# SCA ecosystem examples

These eight fixtures provide one vulnerable and one clean dependency tree per ecosystem. Scan each directory independently: other examples elsewhere in this repository also contain vulnerable dependencies. The small programs exercise ordinary library calls; expected SCA findings are based on package versions.

The baseline was verified on **2026-09-10** against the [OSV API](https://google.github.io/osv.dev/post-v1-querybatch/). "Clean" means no known advisories for any resolved direct or transitive application package on that date. It is a dated baseline and should be checked again as advisories change. Build-tool installations and operating-system packages are outside this application dependency inventory.

| Fixture | Direct packages | Transitive packages | Vulnerable packages |
| --- | ---: | ---: | ---: |
| `maven-vulnerable` | 1 | 1 | 2 |
| `maven-clean` | 1 | 1 | 0 |
| `npm-vulnerable` | 2 | 1 | 2 |
| `npm-clean` | 2 | 1 | 0 |
| `pypi-vulnerable` | 1 | 4 | 2 |
| `pypi-clean` | 1 | 4 | 0 |
| `cpp-vulnerable` | 1 | 1 | 2 |
| `cpp-clean` | 1 | 1 | 0 |

Counts refer to distinct packages with advisories, rather than the number of CVEs or aliases. npm audit can additionally flag `mkdirp` because it depends on vulnerable `minimist`.

## Dependency paths and expected findings

| Ecosystem | Vulnerable dependency path | Clean dependency path |
| --- | --- | --- |
| Maven | `commons-text:1.9 -> commons-lang3:3.11` | `commons-text:1.15.0 -> commons-lang3:3.20.0` |
| npm | Direct `lodash@4.17.11`; `mkdirp@0.5.0 -> minimist@0.0.8` | Direct `lodash@4.18.1`; `mkdirp@0.5.6 -> minimist@1.2.8` |
| PyPI | `requests==2.28.0 -> urllib3==1.26.12` plus the three packages below | `requests==2.34.2 -> urllib3==2.7.0` plus the three packages below |
| C/C++ | `libpng/1.6.50 -> zlib/1.2.11` | `libpng/1.6.58 -> zlib/1.3.2` |

Maven coordinates in the table use group `org.apache.commons`. Both Python trees also include `certifi==2026.7.22` and `idna==3.19`; `charset-normalizer` is `2.0.12` in the vulnerable tree and `3.5.1` in the clean tree. All of those transitive packages were audited too. The clean npm fixture retains the patched `mkdirp` 0.5 line so its `minimist` dependency remains transitive.

Each vulnerable tree has both a direct and a transitive package with a known advisory. Representative findings are:

[sca-audit.json](sca-audit.json) records every resolved package, its relationship and dependencies, the exact OSV query, all returned advisory IDs, and fingerprints of the dependency inputs. C/C++ queries use upstream release commits because OSV does not accept a `Conan` ecosystem query. Their upstream references are recorded in the report. The pinned Conan recipes apply no security backports to the vulnerable releases used here.

## Recheck the baseline

From the repository root, with Python 3.10 or later and internet access:

```sh
python scripts/check_sca_examples.py
```

The checker queries OSV for all packages, requires at least two vulnerable packages in each vulnerable fixture and zero in each clean fixture, and fails if a dependency input has changed since the inventory was captured. It handles paginated responses and treats API failures as errors. To save a fresh dated report for the same dependency inputs:

```sh
python scripts/check_sca_examples.py --output sca-audit.json
```

When changing dependencies, resolve the complete tree again, update the corresponding package inventory, upstream commit mappings, and input fingerprints, then recheck. Fingerprints are SHA-256 over UTF-8 text with line endings normalized to LF. The checker rechecks the recorded inventory; the package-manager commands below regenerate the underlying graphs and locks.

## Build and inspect the examples

Commands below run inside either directory of the corresponding pair. Use the committed lockfiles when reproducing the baseline.

### Maven

Requires Maven 3.9 and JDK 11 or later. `pom.xml` declares Commons Text directly; its published POM pins Commons Lang transitively. `dependency-tree.json` is generated by Maven.

```sh
mvn compile dependency:tree
mvn dependency:tree '-DoutputType=json' '-DoutputFile=dependency-tree.json'
mvn dependency:copy-dependencies '-DincludeScope=runtime'
```

Run on Linux/macOS:

```sh
java -cp 'target/classes:target/dependency/*' com.northbeam.sca.Application
```

Run on Windows:

```powershell
java -cp 'target/classes;target/dependency/*' com.northbeam.sca.Application
```

### npm

Requires Node.js 18 or later and npm with lockfile v3 support. `package.json` declares the roots; `package-lock.json` pins the complete tree with integrity hashes.

```sh
npm ci --ignore-scripts
npm ls --all
npm start
npm audit
```

The clean audit should exit 0. The vulnerable audit should report findings and exit nonzero. When intentionally updating the fixture, regenerate the lock with `npm install --package-lock-only --ignore-scripts`.

### PyPI

Requires Python 3.10 or later. `requirements.in` contains the direct dependency. `requirements.txt` is the pip-tools lock with exact versions, distribution hashes, and `# via` annotations identifying transitive dependencies. The vulnerable fixture's constraint keeps urllib3 vulnerable without adding it to the direct requirements.

Create and activate a virtual environment in the chosen example, then run:

```sh
python -m pip install --require-hashes -r requirements.txt
python -m pip check
python app.py
```

In a separate tooling environment with pip-tools and pip-audit installed, the following commands regenerate the lock and audit all its packages:

```sh
pip-compile --generate-hashes --output-file=requirements.txt requirements.in
pip-audit --require-hashes -r requirements.txt
```

The clean audit should exit 0; the vulnerable audit should report Requests and urllib3.

### C/C++ (Conan 2)

Requires Conan 2, CMake 3.15 or later, and a C++ compiler. `conanfile.py` declares libpng directly and uses `override=True` to pin zlib transitively. `conan.lock` pins recipe versions and revisions. `dependency-tree.json` records Conan's dependency edges, including the root's `direct: false` zlib relationship.

Create a default profile with `conan profile detect` if one does not already exist. Then run:

```sh
conan install . --build=missing
cmake -S . -B build '-DCMAKE_TOOLCHAIN_FILE=build/generators/conan_toolchain.cmake' '-DCMAKE_BUILD_TYPE=Release'
cmake --build build --config Release
conan graph info . --filter=dependencies --format=json --out-file dependency-tree.json
```

The executable is `build/sca_png_demo` with a single-configuration generator, or `build/Release/sca_png_demo.exe` with Visual Studio. It prints the linked libpng version. To refresh recipe revisions intentionally, regenerate the lock with `conan lock create . --lockfile= --lockfile-out conan.lock` and re-audit the resolved packages.

## Verification performed

Both Maven programs compiled and ran, both npm examples installed with `npm ci` and ran, both Python examples installed with hash verification and passed `pip check` and their smoke runs, and both C++ examples built and ran through Conan/CMake with MSVC. Native npm audit and pip-audit confirmed the expected positive/negative split; the recorded OSV checks cover all eight complete application dependency inventories.

Tools used: Maven 3.9.16 / JDK 22, Node.js 22.22.0 / npm 10.8.2, Python 3.13 / pip-tools 7.6.1 / pip-audit 2.10.1, and Conan 2.32.0 / CMake 3.31.10 / MSVC 19.40 on Windows.
