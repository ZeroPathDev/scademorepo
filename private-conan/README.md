# Private Conan lockfile inventory

The committed lockfile was generated by Conan 2.22.2 from the real private recipe
in `registry-fixtures/packages/conan` and Conan Center's `fmt/11.0.2`. It records
the recipe revisions, including the internal package and its public dependency.

To reproduce locally with Conan 2 and a C++ compiler:

```sh
conan profile detect
conan export ../registry-fixtures/packages/conan
conan lock create . --lockfile-out=conan.lock
conan install . --build=missing --output-folder=build
cmake -S . -B build -DCMAKE_TOOLCHAIN_FILE=build/conan_toolchain.cmake -DCMAKE_BUILD_TYPE=Release
cmake --build build
./build/private_policy
```

For a private server, publish this recipe with `conan upload` using a separate
publishing account, then regenerate the lockfile in a clean client cache using
the read-only account and the private remote. Keep credentials outside Git.

ZeroPath currently reads `conan.lock`; it does not run Conan to generate a missing
lockfile. This example tests recorded internal inventory, not a new Conan registry
connection or automatic resolution without a lockfile. Its private source also
does not establish public-registry provenance for closing a previous finding.
